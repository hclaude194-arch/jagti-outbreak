# Jagti Outbreak: notes for Claude

Unity 6 (6000.0 LTS) URP project. The owner tests it in Unity on a laptop with Intel Iris Xe graphics, 16 GB RAM. Unity is not available in the cloud container, so nothing can be run there (a type check is possible, see below). Keep C# conservative, and say plainly in PRs that code is untested until the owner presses Play.

- Layout source of truth: `tools/layout/generate_layout.py` → `Assets/Data/campus_layout.json`. Map units are about 1 m. The origin is the central roundabout (map 414, 996), and map up is +Z. After editing, bump `VERSION` (Unity rebuilds the scene when it rises), then run `generate_layout.py` and `generate_terrain.py` in that order.
- Terrain: `tools/layout/generate_terrain.py` (numpy) writes the heightmap, splat, grass and tree data; `--preview` draws a top-down check image into `tools/layout/preview/` (gitignored). Its foothill-ridge shape is a design, not survey data; the owner asked for strong relief (flat terrain was rejected twice). The mess area sits on a terrace about 10-12 m above the girls' hostels and the faculty residences a little higher (`TERRACE_PADS`, owner's instruction). Per the owner's satellite shots (2026-11-19) the spine road is the only road to Annapurna Mess and runs level past the mess and shop fronts (`MESS_LEVEL`, `MESS_ROAD_LEVEL_Z`); the drop is a bank with railings on the road's east side, and there is no retaining wall (the owner rejected it). `tools/blender/render_terrain_views.py [view names]` renders eye-level checks of the terrain into `tools/blender/preview/`. Road heights are solved as one network (`solve_road_profiles`): wider roads first, a road that meets or crosses a solved road or roundabout takes its height there, and each profile is held under `ROAD_GRADE` (9-10 % drives); the ground is laid to them after the plots and terraces, and the plots are levelled again without touching road surfaces, so add new shaping before the road pass. The serpentine's heights are set along its length (pinned `CLOCK_STEPS_RISE` below the porch where the clock tower walk meets it) and the hillside between its legs is shaped from it. The clock tower walk is not a road: `CLOCK_STEPS` in generate_layout.py, flights and landings designed in generate_terrain.py and written to campus_terrain.json (`clockSteps`), built by `clock_steps()` in build_buildings.py, so run build_buildings.py after the terrain. The amphitheatre plot sits `AMPHITHEATRE_DEPTH` below the academic plot (top walk level with the ring road). Trees: the owner's photos show few trees on the campus (2026-11-19), so there are no road avenues except the gate approach, only a sprinkle of bushes and neem inside the campus, chir pines only on the hill by the courts, and scrub forest outside; the pine is a tall trunk with a flat, open crown (`BuildPine` in ProceduralAssets.cs, mirrored by `tree_proto` in render_map_tour.py), never stacked cones.
- C# type check without Unity: `apt-get install mono-mcs`, take UnityEngine.dll/UnityEditor.dll from the NuGet package `unity3d.sdk` 2021.1.14.1, stub URP and Unity.AI.Navigation types, and compile with `mcs`. This catches typos but not Unity 6-only API differences.
- The scene is generated by `Assets/Editor/CampusGreyboxBuilder.cs` (menu Jagti > Build Campus); do not hand-edit `Campus_Greybox.unity`. Textures and tree models are made from code into `Assets/Generated` (gitignored).
- Input: classic Input Manager (`UnityEngine.Input`), not the Input System package.
- Performance targets: 30 fps on Iris Xe, 0.8 render scale, baked lighting, fog-limited draw distance, zone streaming later.
- Blender works headless in the container through `pip install bpy` (Python 3.13; `import bpy` before `bmesh`). `tools/blender/build_buildings.py` builds the landmark FBX files from campus_layout.json (`--render` writes Cycles previews to `tools/blender/preview/`, gitignored). Git LFS uploads are blocked from the cloud container (lfs.github.com is denied), so the small generated FBX files are plain Git (see .gitattributes); keep them small. Material slot names must match `Assets/Editor/BuildingMaterials.cs`, and the tile sizes in both files must agree. Unity checks each model's bounds against building_models.json and corrects scale, turn or mirror. Coplanar faces flicker black in Unity, so `Model.to_object` runs `separate_coplanar`, which lifts one face of each same-facing overlapping pair by a few millimetres; interior shells are also lifted off their building's faces (`exterior_faces` in build_interiors.py). Keep that pass, and don't count on exact coincidence between faces. Buildings from different layout entries must not touch, because each builds its full facade (Girls Hostel A and B are 4 m apart).
- Building names come from the official campus plan. Treat names marked "?" on the vision map as guesses.
- Gameplay (Phase 3) lives in `Assets/Scripts/Gameplay/` (namespace Jagti.Gameplay); `Assets/Editor/GameplayBuilder.cs` wires it into the scene after the NavMesh bake. Zombies, view models and sounds are built in code at runtime (no prefabs or audio files yet). Each MonoBehaviour needs its own file named after the class.
- Interiors (Phase 4): `tools/blender/build_interiors.py` (run after `build_buildings.py`) writes the interior shell FBX, furniture FBX files in `Assets/Models/Props/` and `Assets/Data/interiors.json`; `Assets/Editor/InteriorBuilder.cs` places them before the NavMesh bake. Exterior doorways are cut in `build_buildings.py` (OUTER_DOORS, courtyard middle bays, BAY_DOOR_SEGMENTS, EAST_DOOR_Z); the interior walls copy the facade's window positions through `facade_openings`, so keep the two in step. `clear_doorways` (build_interiors.py) finds every door threshold in the building models and drops ground-floor furniture that would block it; a hostel entrance keeps its lobby even when it falls in a corner room. Interior floors sit 0.6 m above each storey line. New material slots go in MATERIALS and `InteriorMaterials.cs`. Upper storeys: `level_openings` mirrors `academic_facade` floor by floor, and `hall_bays` (build_buildings) leaves the west facade open where the Mandapam hall covers it; change both sides together. Each level starts from the ground plan (`make_level`); furniture and lights carry a `level`, and `InteriorZone` draws only the camera's storey and its neighbours. Hostels and the mess (Phase 4C) are in `tools/blender/build_hostel_interiors.py`, imported by `build_interiors.py` (one shell and zone per building; props and lights carry `zone`, and zones carry `floorOffset`/`maxLevel`). Hostel rooms follow `hostel_facade` bay by bay (`facade_sides` replays it, and both take each window from `hostel_glass` and `HOSTEL_WIN_Z`), so change the two together; the hostel look (paired deep-set windows, jali stair cores between fins, solar roofs) is from the owner's photos and the satellite view, see project memory; hostel wings in the layout must touch, not overlap, so their corridors can be joined. The mess and medical interiors are drawn in world coordinates at their first spot (`INTERIOR_DESIGN` in build_buildings.py) and shifted to the layout's position, so the layout may move those buildings but must keep their sizes. Shops, the medical centre and the sports complex (Phase 4D) are in `tools/blender/build_civic_interiors.py` (plans written room by room in world coordinates); their shop fronts and doorways come from `SHOP_UNITS`, `SHOP_SIDE` and `CIVIC_DOORS` in `build_buildings.py`, which both files read. The shops are Vipanan (owner's video and photo, 2026-11-19): a single-storey L of two arms (`vipanan()` in build_buildings.py: raised colonnade, deep white fascia band, roof shelter and solar panels) round a paved `plaza` area; its units are furnished from their own shop fronts (`UnitFrame`), so the arms may change size.
- Outdoor props (Phase 4D): `tools/blender/build_outdoor.py` (run after the terrain and `build_buildings.py`) writes the street furniture FBX files and `Assets/Data/outdoor_props.json`; `Assets/Editor/OutdoorBuilder.cs` places them and sets sign text with TextMesh. Placement follows the layout (roads, paths, lawns, courts, places) and the terrain heightmap, so rerun it after layout or terrain changes. Street details from the owner's ground photos (2026-11-19): banner flags along the spine and paved roads (`street_flags`), a shrub-bordered lawn island between Vipanan and the mess (`mess_island`), the kerbed bed, young tree and map board at the split to the girls' hostels (`girls_split`, where `Paved Girls Hostel Lane` leaves the spine road), and rubble stone walls with floodlight masts on the courts' west and north sides where the bank rises (`court_walls`). Low shrubs line the verges of roads 4.5 m or wider inside the campus (the verge block in generate_terrain.py).
- Battle royale (Phase 5, the default mode): runtime code in `Assets/Scripts/Royale/` (namespace Jagti.Royale); `Assets/Editor/RoyaleBuilder.cs` wires it in after the NavMesh bake. **Jagti > Game Mode** (EditorPrefs `Jagti.GameMode`) picks royale or zombie survival for the next build. Loot spots come from `tools/royale/build_loot_points.py` → `Assets/Data/loot_points.json` (run after `build_interiors.py`; `--preview` draws `tools/royale/preview/`). It keeps loot off furniture using `tools/royale/prop_sizes.json`, which `tools/royale/measure_props.py` (bpy) rebuilds when props change. Gun, item and brand names are original; copy no names, characters, art, UI or items from existing battle royale games. Bots (5B): `HumanBody.cs` builds a skinned body with `MeshKit.cs`; `tools/royale/preview_bodies.py` is a numpy port of its build and poses for Blender previews, so change the two together. Difficulty, the think scheduler and the cover search are in `BotTuning.cs`. Guns and attachments (5C): models in `LootVisuals.cs` use one gun frame (barrel +X, top +Z, thickness Y around Yc), with attachment mount points in `MountsFor`; `tools/royale/preview_guns.py` parses that C# to render them, so keep the call forms simple (P, Barrel, b.Box, b.Tube, b.Ball, and one-line `for (int i = 0; i < N; i++) P(...)` loops); `--hero` renders a close-up. The view model's sway, sprint, landing, reload and recoil motion is in `PlayerArsenal.AnimateView`, and the muzzle flash (light plus crossed quads) sits at each gun's muzzle mount. Getting around (5D, 6E): `Vehicle.cs` (four kinds: scooter, utility cart, auto-rickshaw, patrol 4x4; driving, Shift boost tank, H horn, damage) with models in `VehicleModels.cs` (the loot palette, which now has Yellow and Green), `VehicleSpawner.cs` (parking spots found by RoyaleBuilder along roads and car parks), `ZipLine.cs` (sites found by RoyaleBuilder; `tools/royale/preview_getting_around.py` repeats the search on the heightmap) and `PlayerMover.cs` (vaulting, wading in the channels, riding, zipping). `tools/royale/preview_vehicles.py [--fleet]` translates the VehicleModels/ZipLine model code to Python to render it, so keep those to MeshKit calls, simple declarations, foreach over literal arrays and plain for loops. Map for battle (5E): cover models and placement come from `tools/royale/build_cover.py` (bpy; run after `build_outdoor.py` and `build_loot_points.py`) → `Assets/Models/Props/Cover_*.fbx` and `Assets/Data/cover_props.json` (outdoor_props format, placed by OutdoorBuilder in royale builds before the NavMesh bake); rerun it after layout, terrain or outdoor prop changes. `PropCuller` (Assets/Scripts/World) hides outdoor props past per-prop distances set in OutdoorBuilder. Online (5F): `Assets/Scripts/Net` (namespace Jagti.Net, plain C# with no Unity types: `NetPeer` UDP transport, `NetBuffer`) is tested by `tools/net/net_test.cs` with mono (see its header); `Assets/Scripts/Royale/Online` has `NetSession` (DontDestroyOnLoad connection and lobby), `NetLobbyMenu` (front menu; MatchDirector waits for it), `NetMatch` (in-match messages, types in `NetMsg`) and `NetPuppet`. Rules to keep: every machine runs the match from the host's seed, so `LootDirector.SpawnAll`, `PlanFlight` (the first use of MatchDirector's rng), haze centres and `SupplyDrop.Land` must stay deterministic; `Combatant.owned` decides who applies a hit (host owns bots, each player owns themselves; `ReceiveHit` forwards hits on others), so new damage goes through `ReceiveHit`; new loot changes go through `LootDirector.Add/Remove/SetCount`; new throws through `Grenade.Launch`; shots through `Ballistics.Fire`. Online the pause menu doesn't stop time (check `Time.timeScale == 0f`, not just `GameState.Paused`, before freezing match logic).
- HUD and menus (Phase 6A): IMGUI drawn through `Assets/Scripts/Royale/Ui/HudKit.cs` in reference units of a 1080-high screen (palette, generated textures, widgets; draws only on repaint, `useGUILayout = false`). `RoyaleHud` is a partial class: `RoyaleHud.cs` (state, compass, kill feed), `.Combat.cs` (player card, hotbar, ammo, crosshair, drop), `.Maps.cs` (minimap, haze timer, full map), `.Menus.cs` (pause, results); `NetLobbyMenu` is the front menu and shares `MenuPanels` (settings, controls). Settings live in `GameSettings` (PlayerPrefs). Icons are shape strings in `HudIcons.cs`; fonts are Barlow Condensed (OFL) in `Assets/Resources/Fonts` (plain Git, see .gitattributes). `tools/royale/preview_hud.py BACKGROUND.png [MAP.png]` mirrors the layouts with Pillow for mockups, so change the two together.
- Sky bus (Phase 6B): the drop craft is `SkyBus.cs` (flight, burner, sounds) with its model in `SkyBusModel.cs` (campus bus under a hot-air balloon, own 9-slot palette made in RoyaleBuilder). `tools/royale/preview_skybus.py` renders it through the preview_vehicles.py translator, so keep the model code in the same simple forms.
- Loot stashes and rich pickings (Phase 6C): `build_loot_points.py` also writes `stashes` (trunk spots against room walls from `STASH_ROOMS`, a few outside buildings; own rng stream so loot points don't move). `LootDirector.SpawnAll` picks two rich-pickings places (fuller, better floor loot), then fills stashes with sealed items (`LootStash`, `LootDrop.Sealed`) that open with E (`NetMsg.Stash` online). The trunk model is `StashModel.cs`, rendered by `tools/royale/preview_stash.py` through the preview_vehicles.py translator.
- Look pass (Phase 6 polish): `Assets/Editor/AtmosphereBuilder.cs` sets the sun, sky, trilight ambient and exponential fog, makes the global post-processing volume (ACES, grading, split toning, bloom, vignette), adds SSAO to the URP renderer (through serialized fields, since its settings class is internal), a realtime reflection probe, wind, ambient dust and leaves, and the impact materials; bump `LookVersion` there so JagtiProjectSetup rebuilds the scene. Runtime: `VisualQuality` (Low/Medium/High in the settings menu: render scale, shadows, SSAO, bloom, AA, grass), `WindDriver` (global `_JagtiWind` for `Assets/Shaders/JagtiFoliage.shader`, which the tree materials use when it compiles), `AmbientParticles`, `ImpactMarks` (sparks, dirt and bullet marks, called from Ballistics). `tools/blender/preview_look.py` mocks up before/after by shading Cycles light passes the Unity way and applying the grade in numpy; keep its numbers in step with AtmosphereBuilder.
